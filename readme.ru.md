# Yuki WebUI

Веб-панель управления для экосистемы Yuki: небольшое Flask-приложение, отдающее
статику/JS-панель, которая напрямую взаимодействует с `yuki-core` по WebSocket - получает в
реальном времени состояние устройств, команды, метрики, группы, теги и выполняет
административные действия (одобрение/занесение устройств в чёрный список, ротация токена,
журнал аудита).

## Требования

Python 3.10+, зависимости зафиксированы в `requirements.txt` (`Flask==3.1.3`, `Werkzeug==3.1.8`,
`requests==2.34.2`, `psutil==7.2.2`).

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

По умолчанию слушает `127.0.0.1:5000`.

## Вход

По умолчанию используется логин **`admin` / `admin`** (хранится в виде хеша, а не открытым
текстом, начиная с первого запуска) - это позволяет сразу начать работу, но **обязательно
смените его** на панели «Настройки» после входа. Можно также полностью обойти файловые учётные
данные, задав переменные окружения `WEBUI_USER`/`WEBUI_PASS`.

## Конфигурация (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | (генерируется автоматически) | Ключ подписи сессий Flask. Если не задан, один раз генерируется случайный ключ и сохраняется в `.flask_secret` (права доступа 600). |
| `WEBUI_USER` / `WEBUI_PASS` | не задано | Полностью переопределяют файл `.credentials`. |
| `YUKI_WEBUI_DEBUG` | не задано | Включает режим отладки Flask (интерактивный отладчик - только для локальной разработки, никогда не открывайте его наружу). |
| `YUKI_WEBUI_HOST` | `127.0.0.1` | Адрес для привязки. Установите `0.0.0.0`, чтобы панель была доступна с других устройств в вашей локальной сети. |
| `YUKI_WEBUI_TLS_ENABLED` | не задано | Если значение "истинно", сервер работает по HTTPS вместо HTTP - требует двух переменных ниже. |
| `YUKI_WEBUI_TLS_CERT` / `YUKI_WEBUI_TLS_KEY` | не задано | Пути к PEM-сертификату/ключу, используемые при включённом TLS. |
| `YUKI_CORE_TOKEN_FILE` | `../yuki-core/.token` (относительно этого репозитория) | Где искать токен аутентификации `yuki-core`, чтобы авторизовать собственное WebSocket-соединение панели с `/webui`. Переопределите это значение, если `yuki-core` выложен не рядом с этим репозиторием. |

Шифрование **по умолчанию отключено**, как и во всей остальной экосистеме; `SESSION_COOKIE_SECURE`
автоматически следует за значением `YUKI_WEBUI_TLS_ENABLED`.

## Как происходит подключение к `yuki-core`

Функции реального времени панели работают через прямое WebSocket-соединение браузера с
`yuki-core` по пути `/webui` (не проксируется через это Flask-приложение). Поскольку через этот
сокет передаются привилегированные действия, браузер аутентифицирует его сразу после открытия: он
запрашивает текущий токен ядра через собственный эндпоинт этого приложения `GET
/api/core-token` (для чего нужно уже быть авторизованным здесь) и отправляет его первым
сообщением в сокет. `yuki-core` проверяет токен, прежде чем принять что-либо ещё.

## Файлы данных

`dashboard_data.json` (группы/теги/расположение виджетов), `.credentials` (хешированные
имя пользователя/пароль, права доступа 600), `.flask_secret` (права доступа 600), `logs/`
(по одному файлу на запуск).

## Протокол

Использует Yuki Protocol `yuki/1.0` через встроенную копию в `static/libs/yuki-protocol/`
(Python - для собственных серверных хелперов сообщений, JavaScript - для браузера) - см.
[`yuki-protocol`](../yuki-protocol).
